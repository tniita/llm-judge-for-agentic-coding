# r-6692033d

## タスク

注文時の在庫引き当てが一部だけ成功したまま残る不具合を直し、複数スレッドから使っても安全にする。

- `Inventory.reserve_many(items: dict[str, int]) -> None` を追加する

R1: `reserve_many` はすべての SKU を引き当てられる場合だけ在庫を減らす。1 つでも足りなければ OutOfStockError を送出し、どの在庫も変更しない
R2: `OrderService.place_order` は `reserve_many` を使い、在庫不足で失敗したときに在庫が一部だけ減った状態を残さない
R3: `reserve` / `reserve_many` / `release` は複数スレッドから同時に呼ばれても在庫を過剰に引き当てない（スレッドセーフ）
R4: `reserve` / `reserve_many` / `release` に 0 以下の数量を渡したら ValueError を送出する
完了条件: 既存テストと追加したテストがすべて通ること

## PR 説明

# 在庫引当をアトミックかつスレッドセーフにする

## 背景
`OrderService.place_order` は SKU ごとに `reserve()` を順番に呼んでいたため、途中の SKU が在庫不足になると、それより前の SKU だけ在庫が減ったまま残っていました。また `Inventory` はロックを使っておらず、複数スレッドから同時に呼ぶと過剰に引き当てられる可能性がありました。

## 変更内容
- `shoplib/inventory.py`
  - `Inventory.reserve_many(items: dict[str, int]) -> None` を追加しました。ロックを取ったまま全 SKU の在庫を確認し、すべて足りる場合だけ在庫を減らします。1 つでも足りなければ `OutOfStockError` を送出し、どの在庫も変更しません（R1）。
  - `threading.Lock` を追加し、`set_stock` / `available` / `reserve` / `reserve_many` / `release` をロック下で実行するようにしました（R3）。`reserve` は `reserve_many` に処理を任せます。
  - `reserve` / `reserve_many` / `release` は、数量が 0 以下なら在庫を変更する前に `ValueError` を送出します（R4）。
- `shoplib/orders.py`
  - `place_order` がカート全体を `reserve_many` で一度に引き当てるようにしました。在庫不足で失敗した場合、在庫は変更されず、注文も保存されず、カートもそのまま残ります（R2）。

公開 API のシグネチャは変更していません（追加のみ）。

`tests/test_inventory.py` を追加しました。
- `reserve_many` で全件引き当てに成功するケース、在庫不足や存在しない SKU で何も変更されないケース
- `place_order` が一部の SKU だけ在庫不足のとき、在庫・注文・カートが変更されないこと
- 数量 0 / 負数のときに `ValueError` になること
- 複数スレッドから `reserve`、`reserve_many`、`reserve` + `release` を同時に呼んでも過剰に引き当てず、在庫数が整合していること
