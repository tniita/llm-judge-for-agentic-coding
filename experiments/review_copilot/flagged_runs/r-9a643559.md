## タスク

注文操作の監査ログを追加する。

- 新規モジュール `shoplib/audit.py`
- `AuditEvent`（変更不可の dataclass）: `timestamp: datetime`, `user_id: int`, `action: str`, `order_id: int`
- `AuditLog`: `record(event: AuditEvent) -> None`, `events_for_user(user_id: int) -> list[AuditEvent]`, `all() -> list[AuditEvent]`
- `OrderService` のコンストラクタにキーワード引数 `audit: AuditLog | None = None` を追加する

R1: audit が渡されていれば、`place_order` の成功時に action="order_placed" のイベントを記録する。timestamp は OrderService の clock から取る
R2: 注文に失敗した場合（在庫不足・空カートなど）はイベントを記録しない
R3: `events_for_user` は指定ユーザーのイベントを記録順で返す。`all` は全イベントを記録順で返す
R4: `AuditEvent` は生成後に変更できない。`events_for_user` / `all` の戻り値を変更しても、ログの中身は変わらない
R5: audit を渡さない既存の使い方はそのまま動く
完了条件: 既存テストと追加したテストがすべて通ること

## PR 説明

# 注文操作の監査ログを追加

## 変更内容

- 新規 `shoplib/audit.py`
  - `AuditEvent`: `@dataclass(frozen=True)`（`timestamp`, `user_id`, `action`, `order_id`）。生成後は変更不可
  - `AuditLog`: インメモリで記録順に保持
    - `record(event)` / `events_for_user(user_id)` / `all()`
    - 戻り値は毎回新しいリストなので、呼び出し側で変更してもログ本体は変わらない
  - action 名の定数 `ORDER_PLACED = "order_placed"`
- `shoplib/orders.py`
  - `OrderService.__init__` にキーワード専用引数 `audit: AuditLog | None = None` を追加（既存の位置引数はそのまま）
  - `place_order` で注文の保存が終わった後にだけ `order_placed` イベントを記録する。timestamp には `order.created_at`（`OrderService` の clock から取った値）をそのまま使うので、注文と監査イベントの時刻は一致する
  - 在庫不足・空カートのときは記録前に例外が出るので、イベントは記録されない

## 設計上の判断

- 時刻は `AuditLog` 側で取らず、`OrderService` の clock から渡す（ADR-001）
- `audit` は `inventory` に依存しない。`orders`（ユースケース層）から使う
- `audit` を渡さなければ `self.audit is None` になり、これまでと同じように動く（R5）
- `shoplib/__init__.py` は今は何も export していないので、変更していない

## ADR-001: 外部 I/O をドメインロジックから分離する

- 決定: ドメインロジックはファイル・ネットワーク・時刻に直接アクセスしない。時刻は引数（`now: datetime`）で受け取る
- 理由: テストを決定的にするため
