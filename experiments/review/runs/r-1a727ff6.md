# ユーザーごとの API 呼び出しを制限するレートリミッターを追加

## 概要
新規モジュール `shoplib/ratelimit.py` を追加し、トークンバケット方式の `RateLimiter` を実装しました。
キー（ユーザー ID など）ごとに独立して API 呼び出しを制限します。

```python
from shoplib.ratelimit import RateLimiter

limiter = RateLimiter(capacity=10, refill_per_sec=2.0)  # 最大 10 回のバースト、毎秒 2 回分補充
if not limiter.allow(f"user:{user.id}"):
    ...  # 429 Too Many Requests を返すなど
```

## 変更内容
- `shoplib/ratelimit.py`（新規）
  - `RateLimiter(capacity: int, refill_per_sec: float, clock=time.monotonic)`
  - `allow(key: str) -> bool`
- `tests/test_ratelimit.py`（新規）: 要件 R1〜R6 を検証するテストを 23 件追加
- 既存コードは変更していません

## 要件への対応
| 要件 | 実装 |
|---|---|
| R1 トークンバケット | 初めて見るキーは `capacity` 個で開始。トークンが 1 以上なら 1 消費して True、1 未満なら False（消費しない） |
| R2 連続補充・上限 | `allow` 呼び出し時に `経過時間 × refill_per_sec` を補充（遅延評価）。端数も保持し、`min(capacity, …)` で上限を設ける |
| R3 キー独立 | `dict[key] -> (tokens, last_time)` でキーごとに状態を持つ |
| R4 引数検証 | `capacity < 1` または `refill_per_sec` が 0 以下なら `ValueError`。`not refill_per_sec > 0` で判定しているため NaN も拒否する |
| R5 スレッドセーフ | 時刻取得・補充・判定・消費をまとめて 1 つの `threading.Lock` の中で行い、check-then-act の競合を防ぐ |
| R6 時計の差し替え | 時刻は常にコンストラクタで受け取った `clock()` から取得する（デフォルトは `time.monotonic`） |

### 設計上の判断
- **時計の巻き戻り**: `clock` が過去の値を返した場合、経過時間を 0 として扱います（トークンは増えも減りもしません）。デフォルトの `time.monotonic` では起こりませんが、差し替えた時計の安全策です。
- **拒否された呼び出し**: トークンを消費しません（拒否され続けても、補充されれば再び許可されます）。

テストでは `FakeClock` を差し替えて時間経過を決定的にシミュレートしています。主な観点:
- 満杯から開始し、capacity 回まで許可、その次は拒否（R1）
- 端数を含む補充（0.25 秒で 0.5 トークン → 不可、さらに 0.25 秒で可）、および長時間放置しても capacity を超えないこと（R2）
- キー間で消費・補充が干渉しないこと（R3）
- 不正な capacity / refill_per_sec（0、負数、NaN）で `ValueError`（R4）
- 16 スレッド × 100 回を同時に呼び出しても、許可回数がちょうど capacity になること（固定時計／実時計の両方）（R5）
- 注入した clock が使われること、デフォルトが `time.monotonic` であること（R6）

## 既知の制約・今後の検討事項
- **キーの状態は削除されません**: キーの種類が無制限に増える環境（例: 未認証の IP アドレスをキーにする場合）ではメモリが増え続けます。必要になれば、満杯まで回復したキーを定期的に削除する処理を追加できます。
- **ロックは全キー共通で 1 つ**: 処理が O(1) で短いため実用上は問題ない想定ですが、非常に高い並列度で競合が問題になる場合は、キーごとのロックやロックの分割を検討してください。
- **プロセス内のみで有効**: 複数プロセス・複数サーバー間では状態を共有しません。分散環境では Redis などの共有ストアを使った実装が必要です。

+"""ユーザー（キー）ごとの API 呼び出しを制限するトークンバケット方式のレートリミッター。"""
+
+import threading
+import time
+from collections.abc import Callable
+
+
+class RateLimiter:
+    """キーごとに独立したトークンバケットで呼び出しを制限する。
+
+    - 各キーは満杯（``capacity`` 個）の状態から始まる。
+    - ``allow`` が True を返すたびにトークンを 1 消費する。トークンが 1 未満なら False。
+    - トークンは経過時間 × ``refill_per_sec`` だけ連続的に補充され、``capacity`` を超えない。
+    - 時刻は ``clock`` から取得する（テストで差し替え可能）。
+    - スレッドセーフ。
+    """
+
+    def __init__(
+        self,
+        capacity: int,
+        refill_per_sec: float,
+        clock: Callable[[], float] = time.monotonic,
+    ) -> None:
+        if capacity < 1:
+            raise ValueError(f"capacity must be >= 1, got {capacity!r}")
+        # `not x > 0` とすることで NaN も拒否する
+        if not refill_per_sec > 0:
+            raise ValueError(f"refill_per_sec must be > 0, got {refill_per_sec!r}")
+        self._capacity = capacity
+        self._refill_per_sec = refill_per_sec
+        self._clock = clock
+        # key -> (残りトークン数, 最終更新時刻)
+        self._buckets: dict[str, tuple[float, float]] = {}
+        self._lock = threading.Lock()
+
+    @property
+    def capacity(self) -> int:
+        return self._capacity
+
+    @property
+    def refill_per_sec(self) -> float:
+        return self._refill_per_sec
+
+    def allow(self, key: str) -> bool:
+        """``key`` の呼び出しを許可するなら True を返し、トークンを 1 消費する。"""
+        with self._lock:
+            now = self._clock()
+            bucket = self._buckets.get(key)
+            if bucket is None:
+                tokens = float(self._capacity)
+            else:
+                tokens, last = bucket
+                # 時計が巻き戻った場合は補充しない（トークンを減らしもしない）
+                elapsed = max(0.0, now - last)
+                tokens = min(float(self._capacity), tokens + elapsed * self._refill_per_sec)
+
+            if tokens >= 1:
+                self._buckets[key] = (tokens - 1, now)
+                return True
+            self._buckets[key] = (tokens, now)
+            return False
