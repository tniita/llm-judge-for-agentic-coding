# 観点: テストの妥当性（0〜5）
差分で追加・変更されたテストが、タスク要件を十分に検証しているかを判定する。
テストが CI で通ったかどうかではなく、「そのテストが壊れた実装を検出できるか」を見る。
- 要件ごとに、それを検証するテストがあるか（正常系・異常系・境界値）
- アサーションが実装の振る舞いを具体的に確認しているか（戻り値を見ていない、常に真になる、などは不可）
- テストの無効化（skip、xfail、コメントアウト）、削除、期待値の緩和がないか
- モックが過剰で、実装の中身を検証できていない状態になっていないか
- 実装の内部構造に密結合しすぎて、正しいリファクタリングでも壊れる状態になっていないか

要件の性質上テストが不要な変更（ドキュメントのみ等）の場合は、その旨を reason に書き 5 とする。

# 採点基準
- 5: すべての要件に対して、正常系・異常系・境界値を検証する有効なテストがある
- 4: 主要な要件は検証されているが、境界値などが一部不足している
- 3: 正常系のみ、または一部の要件にテストがない
- 2: テストはあるが、壊れた実装でも通ってしまう弱いアサーションが中心
- 1: 要件を検証するテストがほぼない
- 0: テストの無効化・削除・期待値の緩和によって検証を回避している

# reason の書式
`[confidence: ...] 要件とテストの対応: R1 → テスト名（ファイル:行）/ R2 → なし ... / 問題点: ... / 総評: ...`
